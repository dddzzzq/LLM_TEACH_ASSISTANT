# 日志搜索与查阅

管理员登录后从侧栏进入“日志查阅”（`/logs`）。管理员在作业抓取面板点击“查看任务日志”会直接带入任务 ID，关联的抓取、下载和批改记录可以一起检索。教师和学生不显示日志入口，直接访问页面会跳转，调用日志接口返回403。

## 使用方式

- 按关键词、关联任务、来源、级别和时间组合筛选。多个关键词同时匹配，`%`、`_` 按普通字符搜索；最多 300 字、8 个词。
- 时间统一显示为北京时间，可选择最近 1 小时、24 小时、7 天、30 天或自定义范围。原记录没有时间时显示“≈ 时间估算”，不可据此计算精确耗时。
- 默认隐藏 HTTP 访问记录。结果按时间倒序，100 条一页；“更早日志”使用游标分页，新增日志不会使已打开的分页重复跳动。
- “上下文”显示同一文件附近最多 17 行，或者同一任务相邻事件。
- 可展开、复制内容，或导出当前已执行筛选的最多 2000 条 TXT。修改筛选后先点击“搜索日志”，再导出。
- 可开启每 5 秒刷新；打开上下文、查看旧分页或浏览器标签隐藏时暂停刷新，防止打断查阅。

## 可见范围与脱敏

日志查询、来源、任务列表、上下文和导出接口仅允许管理员使用。管理员可以查看所有索引内容，包括 Kafka 和前端服务日志；教师即使是任务发起人也不能访问日志接口。教师原有作业管理、拉取、材料整理、发起批改与成绩查询功能保留；学生只能查询自己的成绩。

只索引固定运行日志文件和任务状态/事件。不会通过接口读取任意文件，也不会跟随日志符号链接。密码、API key、认证头、Cookie、常见令牌、私钥块和带签名链接等在入库前脱敏，返回与导出时再次脱敏。检索接口不写入访问日志，其他访问日志省略查询参数，防止把检索内容反复记入日志。

历史服务日志没有任务 ID 的行也仅管理员可查。新批改流程主要阶段的日志已补充任务 ID；其他组件没有任务标记的输出仍属于系统日志。此页面不恢复原日志未记录的信息，也不保证遮盖任意未识别的自定义敏感字段；排查时仍应避免把密钥写入原始日志。

## 存储与运行

沿用已有 MySQL，无需安装额外日志服务。当前 Windows 部署实际由 WSL 运行，索引使用现有数据库，文件来自 `RUNTIME_DIR`（本机为 `/opt/teaching-runtime`，WSL 虚拟磁盘放在 D 盘）。

固定文件：`backend.log`、`rpa.log`、`ai.log`、`kafka.log`、`frontend.log`。附加从 `rpa_jobs` 的事件记录和 `async_jobs` 的批改状态生成任务事件，不索引题目、批改标准或学生作业正文。

服务启动时创建 `log_entries`、`log_task_links`、`log_file_cursors` 三张索引表。后台每 3 秒增量读取；文件偏移随索引一起提交，支持重启续读、截断与文件替换。每轮每个文件最多 2 MiB、2000 条，单轮有超时限制，历史数据通过多轮补齐，页面显示尚待索引的大小。

索引清理以最近 30 天为界，约每小时检查，积压记录分批继续清理。只删除索引和关联关系；原始日志、任务、下载文件都保留。原始日志的轮转与占用仍需按运行环境管理。索引清理不能代替原始文件轮转。

## 接口与验证

所有接口均要求登录，且角色为 `admin`：

| 接口 | 功能 |
| --- | --- |
| `GET /api/logs/sources` | 可见来源、文件和索引进度 |
| `GET /api/logs/tasks` | 最近可见任务，最多 100 个 |
| `GET /api/logs/search` | 条件检索与游标分页 |
| `GET /api/logs/entries/:id/context` | 授权范围内上下文 |
| `GET /api/logs/export` | 筛选结果 TXT 导出 |

检索与导出需要 `from`、`to`（RFC3339），可选 `q`、`task_id`、`source`、`level`、`hide_http`。查询失败与没有结果分别显示，错误响应不包含数据库细节或原始配置。

Go 测试覆盖脱敏、索引幂等、增量追加、文件截断、权限、上下文、分页、字面关键词及清理。集成测试必须设置隔离的 `RPA_TEST_DSN`，数据库名包含 `/rpa_test_`，禁止对业务数据库运行。运行 `go test ./internal/logbook ./internal/handlers ./internal/mq ./internal/rpa`；未配置测试数据库时集成用例会跳过。

前端浏览器交互测试为 `vue-grading-frontend/tests/logbook_smoke.py`，使用独立测试页面和模拟接口，覆盖筛选、任务跳转、分页、上下文、自动刷新暂停、复制、导出及移动端布局；不操作真实任务。生产构建使用 `npm run build`。
