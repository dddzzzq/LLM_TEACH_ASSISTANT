# 作业拉取、材料整理与批改

本次将下载和批改的自动耦合拆开，增加独立材料整理任务。原有页面 Agent、浏览器 Worker 和评分引擎继续复用；不需要新增 Agent。

## 入口与默认行为

主助手使用两个业务 Skill：`download-homework` 组织官网下载，`grade-homework` 组织批改。页面 Agent 继续使用 `fetch-homework` 导航官网，试卷 Skill 不受影响。

| 核心 Tool | 功能 |
| --- | --- |
| `fetch_homework` | 创建官网下载任务，`after_download` 默认 `extract`，下载并解压后停止 |
| `extract_homework_files` | 从本机目录、ZIP/RAR/7z 或已下载附件创建材料批次；默认不批改 |
| `start_grading_job` | 主动提交已有 `batch_id`，或使用 `directory_path` 先整理再批改 |

`fetch_and_grade_homework` 仅保留兼容名称，与 `fetch_homework` 使用相同参数和默认行为，不能根据旧名称推断会自动批改。`trigger_async_pipeline` 保留旧 ZIP 直接批改入口。

辅助 Tool：`get_fetch_job` 及暂停/恢复/取消下载，`get_homework_materials`、`cancel_homework_materials`，以及 `inspect_grading_target`、`get_grading_job`。长任务受理后返回真实 ID 并结束聊天本轮，由后台推进。

## 三种用法

1. 只拉取并整理：加载 `download-homework`，调用 `fetch_homework`，传课程名、作业名，可指定 `output_root`。`after_download=extract` 完成后等待老师主动批改；`download` 则只保留原始下载附件，不创建整理批次。
2. 完整拉取到批改：在调用下载前同时加载 `download-homework` 和 `grade-homework`，下一轮设置 `after_download=grade`。后台保存后续意图，下载、整理成功且评分配置齐备后创建独立批改任务。缺项时等待补充；异常材料不会静默进入自动批改。
3. 指定位置批改：加载 `grade-homework`，核对作业 ID 和评分标准；`start_grading_job` 传 `directory_path`。也可先 `extract_homework_files` 仅整理、检查清单，再以 `batch_id` 发起。若目录正是本人已有批次的解压位置，直接复用该批次。

独立整理已下载附件时传 `source_job_id` 和 `source_file_id`，不猜测下载路径。查询下载任务可得到附件和 `material_batches`。仅在老师明确要求整理后批改时传 `auto_grade=true`。

## 目录和清单

Windows 的 `D:\...` 在 WSL 中映射为 `/mnt/d/...`，默认整理根目录为项目的 `homework/`，本机位于 D 盘。

结构为：`保存根目录/课程/作业/班级/批次ID/执行ID/`。该目录下保存 `original/`（直接导入的原始压缩包副本）、`students/` 和 `manifest.json`。执行 ID 使服务中断后的重试与未完成文件隔离。目录导入会复制识别出的学生文件，保留输入文件，不移动原件。

课程、作业、班级名称经过目录名清洗；每个批次独立。学生内部路径保留，`src/main.py` 与 `test/main.py` 不会相互覆盖。身份从文件或上级目录中的 `学号-姓名`、`学号_姓名`、`学号姓名` 识别；学号为字符串，5–20 位数字。程序、报告和其他附件分别列入清单。

重复学号的多个压缩包、姓名冲突、无法识别的文件、损坏或加密压缩包等生成异常。冲突学生从可批改清单中排除。`NEEDS_REVIEW` 批次默认禁止自动批改；老师检查后可明确选择 `allow_partial=true`，只批改已成功识别的学生。

独立整理支持 ZIP、RAR、7z 及其混合嵌套，目录导入和作业详情页上传共用此实现。7z 使用编入后端的 Go 解码库，无需安装额外的 7-Zip 程序；支持中文路径、固实压缩，检查解压长度和可用的文件 CRC32。加密、损坏或不支持的压缩算法会生成异常，不将不完整学生材料交给批改。限制包括压缩包 2GiB、单文件 256MiB、累计解压和复制 8GiB、30000 次文件写入、6 层嵌套以及单次整理 15 分钟。虚拟环境、依赖、缓存和构建目录在解压写入前过滤，不消耗写入预算。符号链接不落盘：忽略目录内的链接计入过滤统计，其他链接记录异常后继续处理正常文件；越界和重复归档路径继续拦截。

单份提交损坏或不完整时，该学生不进入可批改清单，其他完整学生保留。触及全局预算后停止扫描，已完成学生生成有效清单并标为 `NEEDS_REVIEW`，异常中说明后续材料尚未处理；没有可用学生时为 `FAILED`。清单及整理日志记录过滤条目和跳过链接数。

可选环境变量：`HOMEWORK_MATERIALS_ROOT` 指定默认根目录；`HOMEWORK_ALLOWED_ROOTS` 使用 `|` 分隔允许的绝对根目录。默认允许当前项目、材料根目录和本机 `/mnt/d/dzq`。输出不得位于正在扫描的输入目录内部，避免递归导入自己的结果。浏览器里指定的是服务器所在电脑的路径。

## 持久化与恢复

新增 `material_batches`：保存发起人、来源、所属作业、保存位置、清单、准备状态、后续批改意图及关联任务。

整理状态为 `PENDING → PROCESSING → READY / NEEDS_REVIEW / FAILED`，也可取消。后台用持久租约领取任务、定时续租，服务中断后约一分钟可重新领取未完成任务。取消会停止续租并取消整理上下文，已写文件保留，取消状态不会被迟到回执覆盖。

失败或需要核对的批次可点击“重新解压（不批改）”，复用原附件并在新的执行目录重试，无需重新拉取。旧执行目录保留；重试清除先前自动批改意图，完成后等待老师主动开始批改。已取消、材料已就绪或已有批改任务的批次不能重试。下载面板同时展示后续整理的进行中、失败和需要核对状态。

批改与材料准备分开：只有显式请求才创建 HOMEWORK 任务。新批次使用稳定批改 ID，多次点击不会重复创建；新任务先保存完整队列投递信息，再发送 Kafka，发送失败或两步之间中断会由后台重试。队列至少一次投递，消费者继续依赖任务 ID、Redis 锁和持久终态防止重复执行。

批改记录包含材料批次 ID、原始文件清单哈希以及题目/评分标准快照。开始评分前再次核验文件，材料改变时拒绝执行。新材料批次沿用现有解析、查重、AIGC 和综合评分引擎，不对历史批次混合进行成绩池化；程序/报告分类清单不代表本次已新增独立分项计分模型。成绩保存批次和任务来源，可按 `batch_id` 查询或导出。

查重的报告、代码提示词统一采用教学场景口径：`initial_score` 仍是本地模型的初步语义相似度；兼容字段 `llm_analysis.similarity_score` 表示考虑合理复用、独立思考和理解后的抄袭风险分数。具体且可核对的独立分析、实现取舍和改进应降低风险，只有核心内容大范围实质重复、独立贡献很少时才给85分及以上的高风险分数；改名、排版或空泛声明不视为独立贡献。极高风险仅作为评分核对参考，不凭该分数自动扣分。新提示词用于后续分析，历史查重报告和成绩不会自动重算。

下载取消会终止尚未创建批改任务的后续材料流程；已创建的独立批改任务不被下载取消隐式撤回。材料也可单独取消。历史下载任务没有新的处理意图时，不会因评分标准齐备而重新投递批改；已有取消状态保留。

下载中心的每个附件都绑定到唯一导出记录。触发下载时再次核验记录身份、完成状态和唯一可用按钮，并固定实际 DOM 节点，防止列表刷新后误点其他行。下载由控制器直接激活该控件，避免第一个附件打开的下载悬浮窗遮挡后续按钮；继续使用浏览器下载事件、传输进度和 ZIP 校验。按钮缺失、禁用、隐藏或记录变化时停止该动作，不强点悬浮窗或自动重放不确定的下载。

## 浏览器启动恢复

任务浏览器先确认门户和登录控件可用，再交给教师登录。空响应、连接重置、超时和临时服务错误最多尝试 3 次，单次最多 25 秒，导航恢复总预算 90 秒；两次重试分别间隔 2、4 秒。已出现可用登录框或已登录页面时不重复刷新。重试只用于门户与登录页，不会自动重放导出或批改操作，也不调用大模型。

加载期间可显示浏览器画面和进度；暂停会取消当前加载操作，取消任务会终止后续重试。重试耗尽进入 `WAITING_USER / BROWSER_STARTUP`，保留浏览器，并在全局提醒弹窗和控制台提供“重新加载登录页”，复用原任务。该按钮使用原有 `resume` 接口；登录成功后仍需教师交还自动化。日志记录启动步骤、尝试次数、耗时、域名、HTTP 状态和网络错误码，不记录完整 URL、认证参数或表单内容；恢复成功会清除旧错误状态。

## 网页与接口

作业详情页上传现在仅导入整理，即使尚无评分标准也可上传。材料面板提供目录导入、清单、异常核对、主动批改、取消和本批成绩。官网下载控制台可选择三个处理范围及解压保存位置。全局 `/materials` 页面列出本人材料批次。

登录且角色为教师/管理员后可访问：

| 接口 | 功能 |
| --- | --- |
| `GET /api/materials?assignment_id=...&source_job_id=...` | 本人最近100个批次及关联批改状态 |
| `POST /api/materials` | 创建整理任务，可带 `Idempotency-Key` |
| `GET /api/materials/:id` | 本人批次、解压目录、学生和文件清单 |
| `POST /api/materials/:id/retry` | 使用原附件重新整理失败批次，不发起批改 |
| `POST /api/materials/:id/grade` | 主动批改，可明确 `allow_partial` |
| `POST /api/materials/:id/cancel` | 取消未提交批改的后续处理 |

批次始终按发起人隔离，学生不能调用；管理员也不能仅凭 ID 操作其他人的材料批次。作业资源仍沿用已有教师共享管理规则。

## 课程与作业名称核对

`fetch-homework` 保持原来的“门户→个人空间→课程→作业→目标作业批阅入口→更多→导出作业附件”流程。只在实际课程/作业列表中，由大模型根据页面内容判断精确或近似名称；例如“作业1 / 作业一”及少量错字。候选必须引用当前页面真实控件及同一条记录的名称。大模型用 `request_target_confirmation` 请教师弹窗确认，之后目标更新为实际名称并自动继续；门户、个人空间等普通入口不进行课程名称拦截。

只在页面当前已选学期查找课程，不再提供自动切换学期的工具或第二学期兜底。当前课程列表已查看完整（含必要搜索或分页）仍无可信匹配时，页面 Agent 使用 `request_human` 弹窗提醒“当前页面未找到目标课程，请确认课程名或学期”。用户指定学期与页面当前学期不同，也由教师手动核查或切换，完成后点击“交还自动化”，从当前页面继续原抓取流程。执行器阻止用普通 click/fill 自动操作学期控件，转为同样的人工提醒。

页面观察通过 `active_page_id` 标记当前标签页，`frames/elements` 只含该页内容，其他页保留摘要供模型明确切换，避免旧门户入口与当前课程页混淆。打开新标签后接管新页继续原流程。读取页面不匹配名称、弹窗或操作学期控件。

教师因课程名/学期提示手动处理后交还自动化时，若当前页能唯一读取到已选学期，则将该实际学期保存到目标，原输入保留在 `requested_target`，避免仍按旧学期重复提醒；此步骤只读取页面，不操作下拉框。

待确认状态为 `TARGET_SUGGESTION`，携带 `target_resolution`（确认 ID、目标类型、原名称、候选、所在学期及大模型判断理由）。`POST /api/rpa/jobs/:id/resolve-target` 接受 `resolution_id` 和 `choice=confirm,candidate_id`，或 `choice=edit,name`。确认时重新核验页面候选和学期，拒绝过期确认及导出后的目标变更；成功即恢复自动执行。`requested_target` 保留原输入，`target_resolutions` 留下教师接受的名称和学期。实际名称同步到下载任务，用于后续材料目录和作业匹配。

名称匹配使用原页面 Agent 的逐步决策循环，没有额外的后台匹配轮询或独立匹配模型。候选确认期间不调用页面模型。新会话重试在导出前加载当前导航 Skill/工具协议，旧动作回执仍先核对，不重复提交导出。

## 验证

`go test ./...`；隔离数据库设置 `RPA_TEST_DSN` 后，运行材料、批改、RPA、Handler、MQ、流水线集成测试。测试数据库名必须包含 `/rpa_test_`，不允许指向业务数据库。测试覆盖无隐式批改、下载到独立整理、幂等、取消恢复、队列重试、快照、越权、文件完整性及现有取消消息防重放。

`vue-grading-frontend/tests/materials_smoke.py` 使用浏览器和模拟接口检查默认不批改、显式接续、清单、部分批改同意、取消和移动端布局，不发起真实评分。生产构建为 `npm run build`。

`tests.test_target_confirmation`、`tests.test_page_navigation`、`tests.test_semester_navigation` 验证个人空间入口、原业务链路、读取无副作用、大模型显式候选确认、禁止自动操作原生/自定义学期控件、人工核查后恢复、标签页焦点与过期保护；`rpa_target_resolution_smoke.py` 验证确认弹窗、名称修改及移动端布局，业务接口全部模拟。

`tests.test_download_controls` 使用真实 Chromium 和模拟下载接口，复现第二个按钮被悬浮窗遮挡的场景，验证两个附件连续下载、父页面遮挡 iframe、普通文字下载按钮，以及禁用、隐藏、重复按钮和记录变化时不误触发。
