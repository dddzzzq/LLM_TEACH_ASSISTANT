# 教务自动化设计：复用现有 RPA Agent

版本：V2.1 · 2026-10-25。以现有页面 Agent、任务浏览器和附件下载流程为基础，替代上一版独立认证浏览器与目录遍历设计。

## 设计范围

教师在设置页保存账号密码后，创建一个普通 RPA 任务。它使用原来的 `Task`、Go/Eino 页面 Agent、页面观察与动作回执，以及 `RpaTaskPanel` / `RpaBrowserPanel`，不另建认证浏览器。

账号密码由 Worker 内部读取并填入；页面 Agent 根据当前页面判断是否需要滑块、本人验证码、设备信任或进入课程页面。滑块复用当前已有实现。验证码由教师在任务浏览器填写，交还自动化后由 Agent 提交。账号、密码和验证码都不作为模型动作参数。

首次认证及随后的目录采集在同一个 `AUTH_BOOTSTRAP` 任务、同一浏览器中完成，由同一页面 Agent 加载 `sync-teacher-portal` Skill。已有课程页或登录页先核验复用，不重复进入门户。认证成功便继续采集，目录完整后由一次业务回执发布；已核验身份先保存，采集失败保留上次成功目录。单独更新课程使用 `CATALOG_SYNC`。读取工具只读取当前页面；每门课程（含明确无作业）读完后，Agent 调用原控制器的 `return_to_course_list` 返回已读取的课程列表，继续下一门。`collect-homework` 保留兼容。

## 复用关系

| 能力 | 实现 |
| --- | --- |
| 浏览器生命周期、持久配置 | 原 `Task` 与现有 `PortalSessions` |
| 页面判断与导航 | 原 `browseragent.Decide`、`rpa/navigation.go` |
| 观察、动作校验、回执与恢复 | 原 `/tasks/:id/observation`、`/action` 协议 |
| 手动输入、暂停与交还控制 | 原任务浏览器和 WebSocket |
| 下载指定作业 | 原 `fetch-homework` Skill 与导出/下载控制器 |
| 首次账号设置 | 普通 RPA 任务，`task_type=AUTH_BOOTSTRAP`，加载 `sync-teacher-portal` |
| 获取课程作业目录 | 首次连接延续原 AUTH_BOOTSTRAP；单独更新使用 CATALOG_SYNC，均加载 `sync-teacher-portal` |
| 目录选择与结果保存 | 保留已有目录快照、选择界面与业务数据表 |

`PortalOperation` 只保留设置页的业务状态和事件记录，其 ID 同时作为普通 RPA 任务 ID；不再拥有另一套浏览器控制器或页面决策流程。

## 最少新增动作

| 页面动作 | 职责 |
| --- | --- |
| `fill_portal_credentials` | 在已配置的学校登录来源填写已保存账号密码，至多提交一次 |
| `request_login_code` | 在官网获取验证码，然后交还教师输入 |
| `submit_login_code` | 提交教师已在当前浏览器输入的验证码 |
| `apply_device_trust` | 根据教师设置处理当前可信设备弹窗 |
| `return_to_course_list` | 按已读取列表的内部书签返回原课程页，不接收 URL；无作业也返回继续 |
| `read_course_list` | 读取当前课程列表的官网 ID 与名称 |
| `read_homework_list(course_id)` | 核验当前课程归属，读取班级和作业列表 |
| `select_homework_detail(homework_id)` | 绑定当前已读作业列表中的详情目标，随后由 Agent 点击名称；不接收 URL |
| `read_homework_detail` | 复用原读取器获取目标详情，同步中读完自动回到原作业列表，单独重读仍可使用 HOMEWORK_DETAIL |
| `finish_catalog` | 先返回并重新核验课程列表，完整后提交目录；清单尚未核验到末尾则继续采集 |
| 原 `scroll` | 采集时定位课程/作业所在 iframe 和内部列表，滚动并等待懒加载稳定，参数协议不变 |

前四项认证动作均不接受凭据或验证码参数。现有滑块工具、通用页面导航动作、附件导出、文件关联与校验继续复用。

## 使用流程

1. 教师在“教务账号设置”保存凭据，原任务面板自动打开。
2. Agent 自动填写账号密码，根据观察调用已有校验能力；首次需要验证码时，在同一面板等待本人填写。
3. 教师填写验证码并点击“交还自动化”，Agent 提交验证码，按已保存选项选择信任设备。
4. 身份核验完成，系统安排一个目录采集 RPA 任务。Agent 按 `sync-teacher-portal` 导航、翻页和读取，读完每门课程后返回列表，直到本学期全部课程完成。
5. 教师在工作台选择课程和作业后（默认全部班级，无需班级 ID），创建原 RPA 下载任务。页面 Agent 根据名称、学期及官网 ID 定位；控制器接续导出与下载。
6. “更新课程”再次执行目录采集 Skill，只更新目录。上传压缩包与指定目录继续使用原材料整理和评分服务。

没有设置账号的原下载任务仍可人工登录。已完成账号设置的原名称式下载任务也会复用保存的凭据，不要求改用新的下载入口。

## 保留的必要约束

凭据继续加密保存；浏览器配置按教师连接隔离。模型只看到认证状态与可核验的业务 ID，不读取凭据或表单值。同名目标依靠官网标识区分，标识缺失或页面有歧义时交还教师确认。

目录读取失败或不完整时保留上次成功结果。下载仍按原导出检查点恢复，避免重复提交导出。网站撤销设备信任或再次要求验证时，继续在同一任务浏览器处理。

部署、源码路径和验证说明见 [实现与部署](teacher-portal-automation.md)。
