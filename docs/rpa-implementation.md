# 官网作业下载：人工协作 Agent

入口为「AI 教学助手」对话区，快捷指令提供「从教务系统下载作业并批改」和「查询学生成绩」。对话创建下载任务后，右侧自动弹出作业控制台并选中该任务；可收起控制台，之后从任务消息或「打开作业控制台」按钮重新进入。收起只停止前端浏览器连接与状态轮询，后台任务继续执行。目标固定为西电教学平台，课程、作业名称及可选学期由用户提供；新任务默认自动导出全部班级。

## 模块职责

| 模块 | 实现与职责 |
| --- | --- |
| 对话工具 | `backend-go/internal/agent/tool_fetch_homework.go`：创建、查询、暂停、恢复、取消本人任务，不接收官网密码 |
| 浏览器 Tool | `ai_engine_python/app/rpa/tools.py`：代码定义动作及参数协议，模型提示与执行校验共用；控制器继续核验实时页面及业务范围 |
| 页面 Skill | `skills/fetch-homework/SKILL.md`：登录及下载导航；`skills/sync-teacher-portal/SKILL.md`：首次认证、本学期全部课程作业更新；`collect-homework` 保留兼容。均由原 Go/Eino 页面 Agent 按需加载，任务保留版本快照 |
| 页面 Agent | `backend-go/internal/browseragent/agent.go`：通过 Eino 加载导航 Skill、调用模型并返回一个结构化动作 |
| 平台适配器 | `portal_adapter.py`：观察多页面与 iframe、验证目标、读回班级勾选、提取稳定导出记录；保留旧脚本的站点规则 |
| 页面基础信息 | `page_snapshot.py`：页面/iframe、标题层级、导航分区、控件角色与局部上下文；过滤表单值和 URL 令牌，按预算保留目标信息 |
| 任务控制器 | `task_controller.py`：独立浏览器生命周期、控制权切换、恢复检查、导出防重、下载调度 |
| 文件管理 | `download_manager.py`：临时文件、传输停滞检测、ZIP 非空及 CRC 校验、SHA-256、原子保存 |
| 浏览器 Worker | `worker.py`：独立进程，内部 HTTP 控制 API、任务快照和超时清理，不加载 Skill、不调用模型，也不加载 OCR 或批改模型 |
| Go 调度器 | `backend-go/internal/rpa/`：创建者隔离、数据库状态镜像、派发重试、附件导入、评分标准门控、独立批改任务 |
| Vue 控制台 | `RpaTaskPanel.vue`、`RpaBrowserPanel.vue`、`RpaClassSelector.vue`：任务状态、远程键鼠、异常范围处理、导出记录确认与批改进度 |

## 执行与人工接管

1. Go 保存 `RPAJob` 和异步任务。Kafka 只传任务 ID；数据库中的排队记录也由调度器重试，人工等待不会占用 Kafka 消费线程。
2. Worker 打开任务独立的 Chromium，进入 `AUTHENTICATE/HUMAN`。用户在同一浏览器输入账号密码并提交登录；出现滑块后可点击「交还自动化」，进入 `SOLVE_CAPTCHA/AUTO`，由页面 Agent 调用无参数 `solve_slider_captcha`。工具复用现有 Page/Frame，在内存中识别图像，整轮最多尝试三次；暂停或取消会释放鼠标，失败及其他二次认证交回人工。滑块消失后仍由 Worker 核验登录成功，不能据此直接判定已登录。人工控制期间查询任务只刷新登录状态，不自动操作；完整手动登录仍可正常交还自动化。

   已在设置保存并认证教务账号时，复用该教师的持久浏览器配置，页面 Agent 在 `AUTHENTICATE/AUTO` 调用 `fill_portal_credentials` 自动填写。首次本人验证码在原浏览器中填写并交还控制，Agent 再提交及处理设备信任。设置页也使用原 `RpaTaskPanel`，不另建认证浏览器。认证和目录获取均加载 `sync-teacher-portal`，由同一个页面 Agent 导航；读取工具不自行跳转，每门课程（含明确无作业）读完后，Agent 用 `return_to_course_list` 返回原列表继续下一门。参见 [教务自动化](teacher-portal-automation.md)。
3. Worker 先获取完整页面结构的基础信息，Go/Eino 页面 Agent 加载完整 Skill，依据当前页面所处的业务步骤、控件语义及局部目标上下文选择点击、搜索、滚动、切换页面或请求人工。Go 经内部 HTTP 获取观察，持久保存动作后提交 Worker；观察 ID、revision 和 control_epoch 共同验证。每步重新观察；短暂导航或模型决策失败允许最多三次后再交接，未知回执的旧动作不重放。相同操作须页面也没有变化才计入无进展；目标歧义、认证挑战或预算耗尽仍交给用户。
4. 控制器核验目标并读回班级范围。官网同步创建的作业在详情内选择班级，每个班级复用同一份作业，保留独立材料与结果；新入口的“选择全部班级”会提交目录中的具体班级 ID。旧版未指定班级的请求继续默认全部班级。导出范围、导出格式、命名格式依据 fieldset/ARIA 分组或平台专用容器分别识别，说明中的“班级”字样不作为范围依据。支持原生/ARIA 单选和多选、隐藏原生控件的可见 label、自定义控件及父容器上的选中标记，并等待异步状态更新。导出格式固定为“导出提交附件”，保持命名选项独立；附件格式异常使用 EXPORT_FORMAT 提示，不再次弹出班级确认。
5. 导出前持久化已有记录和提交意图。提交后只跟踪本次新增或有充分更新证据的记录；全部班级的单条目标记录，或与已核验班级一一对应的完整记录集合，可以自动关联。缺少原始记录依据、多个候选等歧义仍要求人工勾选。不会按行号猜测或自动重复导出。用户手动点击导出确认也会记录检查点。
6. 导出记录优先使用平台 ID；没有 ID 时按去除时间和尾部状态的完整名称识别。平台更新完成时间或下载链接不会改变引用；相同名称的多条记录仍视为歧义。旧任务通过唯一名称恢复已确认记录，保留原任务引用，避免重复下载或导入。按当前状态优先下载已成功的记录，不让前面的打包记录阻塞后续附件；状态与日志显示打包数量、下载和 ZIP 校验进度。
7. 下载完成校验 ZIP，再匹配本地作业。班级无法判断时允许更正；题目或评分标准缺失时保留附件并等待。标准齐备后创建稳定的批改任务 ID，投递原有 Kafka 批改流水线。

自动动作期间可请求暂停。先关闭执行门，再等当前浏览器动作结束；模型调用的迟到结果通过 `control_epoch` 丢弃。人工输入校验控制权、页面及画面版本，防止旧画面事件在恢复后执行。文件传输可在暂停期间继续，后续页面动作等待用户恢复。

教师与管理员登录前端后，全局待处理提醒每5秒查询本人任务；收起控制台或切换页面仍会弹窗提示。人工等待按任务、等待原因及控制权轮次区分，同一等待状态在当前浏览器会话只自动提醒一次；主动暂停不额外弹窗。“稍后处理”仅关闭提醒，不确认班级、不交还控制，也不取消任务；右下角“作业待处理”可重新打开或选择其他班级/任务。

附件缺少班级归属时提醒核对班级；缺少题目或评分标准时，弹窗读取已有内容并允许直接补充，评分标准需为非空 JSON 对象。只有点击“保存并继续批改”才写入；保存后沿用原调度器的评分标准门控，自动继续批改。保存失败保留输入；已取消或已开始批改的附件拒绝修改。提醒及补充接口继承教师/管理员角色和任务创建者校验。前端关闭、退出登录或学生身份不运行该提醒。

## 持久化与恢复

页面观察采用 `page.snapshot.v2`，动作协议仍为 `browser.v1`。模型可见观察包含各标签页和
iframe 的标题、URL 路径、标题与导航分区、控件角色/名称/局部上下文、目标核验状态和覆盖率。
原始 DOM、表单值及带查询参数的链接不发给模型。Worker 扫描全部基础控件，模型输入按
约 60000 字符和最多 400 个控件控制，优先保留目标相关信息并显式报告截断。

目标候选按完整业务记录计数。每个控件的 record_id 关联其所属的作业/课程记录，同一记录的标题链接、查看和批阅入口合并；列表行、带业务标识的容器、重复卡片和单标题容器提供记录边界，包含多条记录的外层列表不参与合并。group_count 保留兼容字段名，count_basis=record 明确其含义。真正的同名记录仍交给用户核对，错误日志附候选记录数和不含业务 ID 的临时记录引用。

课程和作业定位增加语义卡片、ARIA 标题、列表项及开放 Shadow DOM 组件支持，导出入口优先按链接、按钮或菜单项的
可访问名称定位；旧站点规则作为兼容路径。导航 Skill 1.2.0 以完整业务目标指导每步操作并减少重复人工交接，
已有任务继续使用创建时的 Skill 快照，新建任务使用新版。班级勾选读回、导出记录关联和文件
下载仍由控制器核验，页面 Agent 不提交导出确认或自行挑选下载记录。

- Go 在 `rpa_jobs` 中保存导航 Skill/动作协议快照、待确认动作和决策租约。模型决策不持有数据库事务；任务间可并行，单任务每次只有一个决策持有者。Worker 持久保存动作摘要与回执，超时后重发同一动作 ID，不重复执行。
- MySQL 使用 `rpa_jobs`、`rpa_files`，由现有 GORM `AutoMigrate` 创建。阶段、已选范围、导出引用和事件保存在状态 JSON；事件不是独立事件表。
- Worker 在 `$RUNTIME_DIR/rpa-tasks/` 原子保存权限为600的任务快照；下载默认在 `downloads/<job_id>/`。Go/Python 需共享文件路径。
- 刷新前端会重新查询本人任务。Worker 重启后未结束任务变为 `INTERRUPTED`；浏览器和 Cookie 不持久化。点击重试后需要重新登录，保留已校验文件及导出检查点。数据库快照也可用于恢复丢失的 Worker 记录。
- 已提交导出的任务重试时先导航到原作业和下载中心，不重新导出。已校验文件跳过，失败文件可以重试。导出记录被平台清理等无法恢复的情形需要人工处理。
- 下载状态与批改状态分开；`SUCCEEDED` 表示下载校验完成，批改完成以附件行的 `SUCCESS` 为准。

账号密码、验证码、表单值、Cookie 和签名下载链接不写入任务日志，也不提供给页面模型。模型不接收截图，只接收经过筛选的页面控件。浏览器画面和人工输入经 Go 的 JWT、教师/管理员角色和创建者校验转发；内部 API 只绑定本机并验证共享令牌。

服务日志中的 RPA event / RPA failure 带任务 ID、阶段、等待原因、受控错误码和代码位置。任务状态包含 last_error，班级/附件核验失败附控件类型、class 和选中状态。第三方异常仅记录类型和栈位置，不输出可能包含令牌的原始异常字符串。前端仅在 TARGET_CONFIRMATION 时显示作业归属确认；普通恢复和范围核验不显示该按钮。

## 人工浏览器响应速度

任务浏览器通过 `/api/rpa/jobs/:id/stream` 建立 WebSocket。连接后第一条消息发送 JWT，令牌不会进入 URL；Go 校验 Origin、令牌有效期、教师/管理员角色及创建者，再通过内部共享令牌连接 Worker。连接不能延长 JWT 有效期。前端在重连前通过现有 HTTP 认证流程检查登录，必要时刷新令牌。

键鼠事件使用 12ms 合并窗口，每条消息最多包含 32 个按序执行的动作。连续文字和鼠标移动合并，按下、释放及 Tab 等离散事件保持顺序；下一条消息不等待上一条确认。Worker 使用独立接收和执行协程，按连接中的递增 ID 返回确认。双方限制队列与传输积压，失败后丢弃未确认输入，不自动重放。切换任务、控制权、隐藏页面或卸载组件会关闭连接并清理待发送输入；断线会释放该连接按下的鼠标，关闭其他查看窗口不会影响正在拖动的连接。

失焦、指针取消和断线清理会先将鼠标移出画面再释放，避免将取消动作变成按钮点击；正常释放仍在用户指定的位置执行。

Worker 为每个任务共享一个 Chromium CDP screencast，推送 JPEG 画面（质量 55、1440×1000，发送上限约 30 帧/秒）。拖动时继续更新画面；慢连接只保留最新待发送帧。静态页面约每秒补一帧，保持点击元数据有效。页面或控制权变化后重新建立对应的画面流，捕获和输入不共用长时间锁。保留最近 128 帧的元数据，仅接受 3 秒内且页面、URL、控制 epoch 一致的按下事件。实际帧率和操作延迟取决于网络、官网与 Chromium，不承诺固定公网延迟。原 HTTP 画面和输入接口仍兼容。

开发环境 Vite 已启用该路径的 WebSocket 转发，并保留 Host 用于 Origin 校验。生产反向代理也需要转发 WebSocket Upgrade；分离部署前端时，将允许的完整 Origin（含协议和端口）加入 Go 环境变量 `RPA_BROWSER_ALLOWED_ORIGINS`，以逗号分隔。

## 运行与验证

项目位于 Windows 磁盘并由 WSL 启动 Vite 时启用 500ms 文件轮询，避免 Windows 写入没有触发 Linux 文件通知而继续提供旧版组件；其他环境保持默认文件监听。

安装 `ai_engine_python/requirements.txt`（含 `websockets==15.0.1`）和 Playwright Chromium 后，在 Python 项目目录运行 `python -m app.rpa.worker`；现有 `scripts/start.sh` 已加入独立 Worker，并检查 `browser.stream.v1` 能力，防止复用缺少流式接口的旧服务。默认端口8765，配置代理后需重启 Worker。更新中的 Go 后端需重新编译并重启，前端需重新构建或由 Vite 热更新。

真实教师账号登录后的课程列表、班级控件和下载中心仍需人工验收。平台改版超出已验证规则时会请求接管，不能保证无人干预完成任意页面。

## Tool 与 Skill 边界

Go Tool 创建和控制持久任务；页面 Tool 执行受限的浏览器动作；`fetch-homework` Skill 提供页面导航知识。修改 Skill 不会增加可执行动作或改变工具参数。工具管理使用 `/api/admin/tools`，旧 `/api/admin/skills` 继续兼容，均不用于编辑 Markdown Skill。详见 [边界与迁移说明](tool-skill-boundaries.md)。

## 导出确认与同名作业重导出

批改下载任务继续使用 `fetch-homework`，`HOMEWORK_DETAIL` 任务才使用 `read-homework-detail`。官网批阅页面标题也可能叫“作业详情”，不能仅按标题判断任务走错流程。

读取下载中心基线后，执行器必须关闭可见浮层并核验关闭结果；“下载中心”入口可能只负责打开，不能再点一次就假定关闭。导出确认使用已核验的官网确认控件，不让浮层遮挡坐标点击。提交意图仍先落盘，确认控件实际激活后才记录“已提交导出”；结果不确定时不盲目重复提交。

官网可能覆盖同名班级作业的旧下载记录，而非新增记录。因此同时保留基线行的显示时间与状态：只有原记录已完成、当前记录名称身份一致、时间已更新且属于本次提交之后，才视为本次重导出。时间用于核验新旧版本，不作为下载引用的稳定 ID；旧的处理中记录后来完成不能自动归到本次任务。全部班级覆盖旧记录时，必须等原有匹配班级记录都更新后再关联，避免只下载第一个班级。作业名匹配支持官网 `(附件)` 后缀，并排除“作业1/作业10”混淆。

Worker 的 `/tasks/{id}/export-diagnostics` 是受控制令牌保护的只读诊断入口，用于检查导出记录和班级控件；不提交导出、不修改页面，也不返回下载签名地址。

官网的自定义班级列表通过 `selectClass(this)` 配合 `li.classli` 的数值 `data` 属性，或 `selectClass(this, 班级ID)` 切换，且切换后网址仍保留旧班级参数。目录读取支持这些控件；具体班级下载先按目录 ID 选择官网选项，再核验页面实际选中状态。明确选中“全部班级”时不能回退使用网址里的旧班级 ID。`fetch-homework` 优先进入作业行的批阅入口，进入仅含题目和答案的预览页时返回列表，不调用题目读取工具。
